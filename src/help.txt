联想拯救者 Y9000P 2022 · 风扇转速管理系统          (EC 层，绕过 Windows 电源计划)

用法:  powershell -ExecutionPolicy Bypass -File src\fanctl.ps1 <命令> [参数]
        或直接双击 风扇控制.cmd

  ── 看 ────────────────────────────────────────────────────────────────
  status                    当前档位 / 温度 / 双风扇转速 / 功耗墙
  watch [-Interval 2]       实时刷新（带目标转速对照）
  history [-Tail 30]        读取历史 CSV（logs\history.csv）
  diag                      一键诊断信息（发我排查用）
  config                    打印 config\config.json
  config check              曲线体检：恒定转速、温度轴倒序等可疑配置（不需要管理员）

  ── 控 ────────────────────────────────────────────────────────────────
  profile [list|名字]       查看/切换档位 quiet 安静 · balanced 均衡
                            performance 野兽 · max 满速 · custom 自定义
  mode [1|2|3]              读/写 Fn+Q 档位（1安静 2均衡 3野兽；本机不支持4）
  set <RPM> [-Seconds N]    直接命令风扇转速（N 秒后自动交还曲线）
  boost [秒]                双风扇满速，默认 20 秒后自动解除
  limit [<PL1> <PL2>]       EC 层 CPU 功耗墙（W）；这项才真正越过电源计划
  limit keep on|off         让守护进程持续把 PL1/PL2 钉在配置值
  curve show|set|export|import [profile] [cpu|gpu] "66:3600,...,94:6600"
                            编辑曲线（CPU 轴=近CPU温度+负载预判；GPU 轴=GPU温度）
  reset                     一键恢复正常：取消满速 + 档位 + 安全转速

  ── 常驻 ──────────────────────────────────────────────────────────────
  daemon start [-Profile 名] [-Interval 秒]     启动闭环守护（需管理员）
  daemon status|stop|restart|log                管理守护进程
  panel [-Port 4765]                            打开可视化调参面板
  test                          端到端自检：逐级升速 + 满速 + 自动恢复
  elevate                       以管理员身份重跑 status
  config reset                  恢复默认配置

安全设计
  · 转速永远被夹在 2400–6600 RPM（实测满速 6600），不会出现 0/低转速失速指令
  · 缺参数或 0 的转速命令会被"拒绝"，不会回落到下限
  · 近CPU ≥ 92°C 或 GPU ≥ 87°C 立即满速，降温 8°C 后自动解除
  · EC 连续读失败 3 次 -> 强制满速，绝不"盲跑"
  · 控制回路连续 3 轮异常 -> 写回安全转速，不再盲目控速
  · 「保持转速/暂停接管」最长 max_hold_s(默认 900 秒)，到点自动交还曲线控制
  · 曲线体检：整条恒定且不等于档位上限 -> 判为误改并告警；解析失败的曲线自动临时改用默认值
  · 守护退出时写回 exit_rpm(4500)，并解除满速
  · 若 EC 主动把 PL1 压低（散热不足信号）而转速未到顶，会自动加 400 RPM
  · 不做定期"心跳重申"：实测每写一次 EC（哪怕同值）风扇都会掉回 ~2600 再花 6–12 秒爬上来

注意
  · EC 会一直保持最后一次命令值；把风扇完全交还 BIOS 自动策略请重启电脑
  · 所有 EC 写入都记录到 logs\fan.log；配置每次改动都留逐项 旧值->新值 差异（旧文件在 state\config.prev.json）
